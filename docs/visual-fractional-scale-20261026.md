# Fractional backing-size edge repaint correction

The existing direct Canvas proxy used the rounded backing-width ratio for both axes. When width and height round differently (reproduced at CSS277×600, DPR1.25 → backing346×750), the scene background covered only749.458 backing pixels vertically. The last pixel row could retain prior-frame color/alpha. Independent probes of Clair, Pathétique, Brahms Lullaby and Canon reproduced this: fresh zero differed from zero→13.7→zero only on the final346 pixels, and the edge was not fully opaque. This is a demonstrated edge repaint bug, not proof of the user's device settings or a cause of perceived stuttering.

The direct proxy now uses independent backing-width and backing-height scale factors in the Canvas transform matrix. It retains the previous x arithmetic and reuses it for y when both ratios are equal. No extra clear/fill/draw, lower resolution, path removal, timing change or scene-source edit is added. The logical line widths and gradient coordinates remain unchanged; under unequal rounded ratios their y mapping has a small intentional pixel difference. This is not universal pixel parity. Existing bounded BWV/Arabesque rendering already uses separate axes and is unchanged.

Writer native evidence: all51 works at integer DPR1/2 and t12 are pixel-identical to the prior runtime (102 comparisons); four representative works across32 fractional/tall/landscape/tiny conditions restore deterministic seeks and full opacity;8 capped-work comparisons remain exact;12 resize comparisons pass. Independent review reproduced old failure/new success on the four affected representative cases and checked non-diagonal matrix coefficients, equal ratios, same-context resize, target A→B→A, throw/finally restoration, dispose/reuse and invalid sizes with the actual factory. Source reverse-check reconstructs the prior renderer byte-for-byte. The regression requires @napi-rs/canvas for native pixels.

No additional rendering commands or full-frame clear are introduced, so there is no duplicate-clear cost. No claim of faster rendering, physical-device FPS or fully resolved stutter is made. Fractional output is intentionally changed at subpixel positions; integer-ratio output is preserved in the sampled native tests. Native software/selected tests are not a full browser/device certificate.
